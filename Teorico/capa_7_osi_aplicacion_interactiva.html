Capa 7 del modelo OSI
Servicios, protocolos y uso real de la red

Presentación interactiva para comprender cómo la capa de aplicación conecta al usuario con la red mediante protocolos como DNS, HTTP, SMTP, FTP y SSH. Está pensada para que el estudiante vea dónde aparece esta capa en situaciones cotidianas: abrir una web, enviar un correo, usar una app o consultar una API.

Comenzar explicación Ir a práctica
01¿Qué hace la capa 7?

La capa de aplicación es la parte del modelo OSI más cercana al usuario. No significa "la app entera", sino el conjunto de protocolos y servicios que permiten que un navegador, un cliente de correo, una terminal SSH o una app móvil usen la red con reglas conocidas.

Web
HTTP / HTTPS
Carga páginas, APIs, imágenes, formularios y respuestas del servidor.
Nombres
DNS
Traduce nombres como utu.edu.uy a direcciones IP comprensibles por la red.
Mensajería
SMTP / IMAP / POP3
Permite enviar correos, recibirlos y sincronizar buzones.
Acceso
SSH / FTP
Sirve para entrar a otro equipo, administrar servicios o transferir archivos.
Idea clave
La capa 7 define qué servicio se quiere usar y qué reglas sigue la conversación. Las capas inferiores se ocupan de transportar los datos; la capa 7 da sentido a esos datos para el usuario y para la aplicación.
Ejemplo 1
Abrir un sitio web
El navegador usa DNS para encontrar la IP y HTTP/HTTPS para pedir el contenido.
Ejemplo 2
Entrar por SSH
La terminal pide autenticación y abre una sesión remota con comandos interactivos.
Ejemplo 3
Usar WhatsApp Web o una API
La app intercambia mensajes y datos con un servicio remoto usando protocolos de aplicación.
02Ubicación dentro del modelo OSI

Selecciona una capa para ver su función. La capa 7 es la cara visible de la red para el usuario: ahí viven los servicios que usamos todos los días.

Relación con las capas inferiores
HTTP no puede funcionar sin TCP o QUIC, y DNS no sirve sin IP y sin enlace de datos. La capa 7 depende de todas las demás, pero es la que decide si el mensaje es una página web, un correo, una consulta DNS o un comando remoto.

04DNS: cómo un nombre se convierte en IP

DNS es uno de los mejores ejemplos de la capa 7: el usuario piensa en nombres, pero la red necesita direcciones IP. Selecciona un tipo de consulta para ver qué devuelve un servidor DNS.

Secuencia real
Cuando escribes una URL, el equipo consulta primero al resolvedor DNS configurado. Si este no conoce la respuesta, pregunta a otros servidores hasta obtener la IP. Recién después el navegador puede iniciar HTTP o HTTPS contra esa dirección.
Consulta práctica
nslookup utu.edu.uy
dig utu.edu.uy
dig utu.edu.uy MX
dig www.google.com AAAA

12Práctica: observar la capa 7 en tráfico real

  

    
Estas actividades permiten ver protocolos de aplicación reales en acción con herramientas conocidas por estudiantes: curl, dig, openssl y Wireshark.


    
Paso 1Analizar DNS

    
terminal

    
sudo tcpdump -i eth0 -nn -s 0 -w dns_query.pcap udp port 53
dig utu.edu.uy
dig utu.edu.uy MX

# Filtros Wireshark:
dns
dns.qry.name == "utu.edu.uy"
dns.resp.type == 1

    
Qué observar
Identificar el nombre consultado, el tipo de registro pedido y la respuesta del servidor. Aquí la capa 7 está resolviendo nombres para que otras aplicaciones puedan seguir trabajando.


    
Paso 2Inspeccionar HTTP

    
terminal

    
sudo tcpdump -i eth0 -nn -s 0 -w http_web.pcap tcp port 80
curl http://example.com

# Filtros Wireshark:
http
http.request.method == "GET"
http.response.code == 200


    
Paso 3Comparar HTTP con HTTPS

    
terminal

    
# HTTP visible
sudo tcpdump -i eth0 -nn -s 0 -w http_plain.pcap tcp port 80
curl http://example.com

# HTTPS protegido
sudo tcpdump -i eth0 -nn -s 0 -w https_tls.pcap tcp port 443
curl https://example.com

# Filtros Wireshark:
http
tls
tcp.port == 80
tcp.port == 443

    
Qué observar
En HTTP se ven claramente el método, la ruta y las cabeceras. En HTTPS se sigue usando HTTP como protocolo de aplicación, pero el contenido queda encapsulado y protegido por TLS.


    
Paso 4Probar una API
