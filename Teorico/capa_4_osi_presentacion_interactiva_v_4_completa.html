Capa 4 del modelo OSI
Transporte, puertos y comunicación

Presentación interactiva para comprender cómo TCP y UDP permiten que las aplicaciones se comuniquen, cómo funcionan los puertos, qué datos aparecen en una captura y cómo analizarlos con Wireshark.

01¿Qué hace la capa 4?

La capa de transporte permite que dos aplicaciones se comuniquen de extremo a extremo. La capa 3 lleva paquetes entre equipos; la capa 4 identifica qué proceso o servicio dentro de cada equipo participa en la comunicación.

Identificación
Puertos
Distinguen servicios: web, DNS, SSH, correo, juegos, etc.
División
Segmentación
Parte los datos grandes en unidades manejables.
Confiabilidad
TCP
Ordena, confirma, retransmite y controla flujo.
Velocidad
UDP
Envía datagramas simples con baja latencia.
Idea clave
IP decide a qué equipo llega el paquete. TCP o UDP deciden a qué aplicación dentro de ese equipo debe entregarse.

09Servicios de aplicación: DNS, HTTP/HTTPS, SSH y DHCP

Los puertos de capa 4 permiten reconocer servicios concretos. En una captura, no alcanza con ver TCP o UDP: también hay que mirar puerto destino, puerto origen, secuencia de paquetes y protocolo de aplicación.

DNS · puerto 53 · UDP/TCP
Resolver nombres a direcciones IP
DNS traduce nombres como utu.edu.uy o example.com a direcciones IP. Normalmente usa UDP/53; puede usar TCP/53 para respuestas grandes o transferencias de zona.
Ejemplo DNS
Consulta y respuesta
Cliente → servidor DNS: “¿cuál es la IP de ubuntu.com?” Servidor DNS → cliente: “ubuntu.com tiene esta dirección A o AAAA”. En Wireshark se filtra con dns.
DNS en terminal y Wireshark
nslookup ubuntu.com
dig ubuntu.com
sudo tcpdump -i eth0 -nn -s 0 -w dns.pcap port 53

Filtros Wireshark:
dns
udp.port == 53
dns.qry.name contains "ubuntu"
Qué observar en DNS
Nombre consultado, tipo de registro A/AAAA/CNAME/MX, servidor DNS usado, tiempo de respuesta y si existe respuesta o error como NXDOMAIN.
HTTP · puerto 80 · TCP
Web sin cifrado
HTTP transporta solicitudes y respuestas web en claro. En una captura pueden verse métodos como GET o POST, cabeceras, host solicitado y códigos de estado.
HTTPS · puerto 443 · TCP + TLS
Web cifrada
HTTPS usa HTTP protegido por TLS. Wireshark permite ver handshake TCP y negociación TLS, pero el contenido queda cifrado.
HTTP y HTTPS
curl http://example.com
curl https://example.com
sudo tcpdump -i eth0 -nn -s 0 -w web.pcap "tcp port 80 or tcp port 443"

Filtros Wireshark:
http
http.request
tcp.port == 80
tcp.port == 443
tls
HTTP
Puerto 80/TCP. Se puede observar el método, URL, cabeceras y contenido si no hay cifrado.
HTTPS
Puerto 443/TCP. Se observa TCP y TLS; el contenido de aplicación viaja cifrado.
Ejemplo de análisis
Primero buscar SYN/SYN-ACK/ACK, luego HTTP GET o TLS Client Hello según el caso.
SSH · puerto 22 · TCP
Administración remota segura
SSH permite iniciar sesión remota, ejecutar comandos y transferir archivos de forma cifrada. Es fundamental en servidores Linux.
Ejemplo SSH
Conexión cliente-servidor
Un cliente abre TCP/22 hacia el servidor. Luego ocurre negociación SSH y el contenido queda cifrado.
SSH
ssh usuario@192.168.1.50
scp archivo.txt usuario@192.168.1.50:/tmp/
sudo tcpdump -i eth0 -nn -s 0 -w ssh.pcap tcp port 22

Filtros Wireshark:
tcp.port == 22
ssh
tcp.flags.syn == 1
Qué observar en SSH
Handshake TCP, versión de protocolo SSH, intercambio inicial y luego datos cifrados. No deberían verse contraseñas ni comandos en texto claro.
DHCP · puertos 67/68 · UDP
Configuración automática de red
DHCP asigna IP, máscara, gateway, DNS y tiempo de concesión. Es clave para que un equipo entre a la red sin configurar todo manualmente.
Secuencia DORA
Discover · Offer · Request · ACK
El cliente descubre servidores, recibe una oferta, solicita una dirección y recibe confirmación final.
DHCP
sudo tcpdump -i eth0 -nn -s 0 -w dhcp.pcap "port 67 or port 68"
sudo dhclient -r
sudo dhclient

Filtros Wireshark:
dhcp
bootp
udp.port == 67 || udp.port == 68
Discover
El cliente pregunta por broadcast si hay servidores DHCP disponibles.
Offer
El servidor ofrece una IP y parámetros de red.
Request
El cliente solicita usar la dirección ofrecida.
ACK
El servidor confirma la concesión. El cliente ya puede usar la configuración.
10Práctica: capturar tráfico con tcpdump y analizarlo con Wireshark

Esta práctica permite observar tráfico real de capa 4. La idea es capturar paquetes en Linux con tcpdump, guardarlos en formato .pcap y luego abrirlos en Wireshark para analizar puertos, protocolos, handshake, retransmisiones y relación entre consulta/respuesta.

Paso 1Identificar la interfaz de red
terminal
ip addr
ip route
tcpdump -D
Paso 2Capturar tráfico y guardar archivo pcap
captura general
sudo tcpdump -i eth0 -nn -s 0 -w captura_general.pcap
Opciones usadas
-i indica interfaz, -nn evita resolver nombres, -s 0 captura el paquete completo, -w guarda en archivo .pcap.
Paso 3Generar tráfico para analizar
ejemplos
curl https://example.com
nslookup utu.edu.uy
ping 8.8.8.8
ssh usuario@servidor
Paso 4Abrir en Wireshark
abrir archivo
wireshark captura_general.pcap
Paso 5Filtros útiles en Wireshark
TCP
tcp
Muestra todas las comunicaciones TCP.
UDP
udp
Muestra datagramas UDP.
DNS
dns
Consultas y respuestas DNS.
HTTPS
tcp.port == 443
Tráfico web cifrado.
Handshake
tcp.flags.syn == 1
Paquetes SYN de inicio de conexión.
Errores
tcp.analysis.retransmission
Retransmisiones detectadas por Wireshark.
