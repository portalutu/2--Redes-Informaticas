01 ¿Qué es una captura de red?

Una captura de red es un registro de paquetes que entran, salen o pasan por una interfaz de red. Cada paquete contiene información organizada en capas: enlace, red, transporte y aplicación. Analizar una captura permite ver qué dispositivos hablan, qué protocolos usan y qué problemas pueden aparecer.

// Capturar
Observar tráfico real
La tarjeta de red recibe tramas. El capturador copia sus encabezados y, si corresponde, parte o todo el contenido.
// Interpretar
Convertir bytes en significado
Wireshark decodifica esos bytes como Ethernet, ARP, IPv4, TCP, UDP, DNS, HTTP, TLS y otros protocolos.
// Diagnosticar
Encontrar pistas
Una traza permite detectar pérdida, retransmisiones, errores DNS, puertos cerrados, latencia o tráfico inesperado.
// Aprender
Ver las capas en acción
Cada paquete muestra cómo una aplicación se apoya en transporte, red y enlace para comunicarse.
02 PCAP: el archivo de una captura

PCAP es un formato usado para guardar paquetes capturados. Un archivo `.pcap` o `.pcapng` puede abrirse luego con Wireshark para estudiar el tráfico sin necesidad de repetir la captura.

// .pcap
Formato clásico
Guarda paquetes con marca de tiempo, longitud y bytes capturados. Es simple y muy compatible.
// .pcapng
Formato moderno
Puede guardar más metadatos: interfaces, comentarios, estadísticas y datos adicionales de captura.
# Capturar con tcpdump en un archivo PCAP
$ sudo tcpdump -i enp0s3 -w practica.pcap

# Leer una captura desde terminal
$ tcpdump -r practica.pcap

# Capturar solo DNS
$ sudo tcpdump -i enp0s3 port 53 -w dns.pcap
03 Wireshark: mirar la red con lupa

Wireshark es una herramienta gráfica para capturar y analizar tráfico. Muestra una lista de paquetes, un árbol de protocolos y los bytes originales. Su valor está en que permite pasar de una línea resumida a una explicación detallada de cada campo.

// Lista de paquetes
Resumen por línea
Número, tiempo, origen, destino, protocolo, longitud e información principal.
// Detalle
Campos por capas
Ethernet, IP, TCP/UDP y aplicación se despliegan como un árbol jerárquico.
// Bytes
Contenido real
Muestra los bytes originales en hexadecimal y ASCII.
// Filtros
Buscar lo importante
Permiten concentrarse en un protocolo, IP, puerto, conversación o error.
# Filtros de visualización comunes en Wireshark
dns
arp
icmp
tcp.port == 80
ip.addr == 192.168.1.10
http.request
tcp.analysis.retransmission
04 Capas OSI y TCP/IP dentro de una captura

Una línea de Wireshark resume un paquete, pero por debajo contiene varias capas. El modelo OSI ayuda a separar responsabilidades; TCP/IP muestra cómo se implementa esa comunicación en redes reales.

OSI 2 / TCP-IP Enlace
Ethernet / ARP
MAC origen, MAC destino, tipo de trama. En LAN responde: ¿a qué tarjeta de red se entrega?
OSI 3 / TCP-IP Internet
IPv4 / ICMP
IP origen, IP destino, TTL, fragmentación. Responde: ¿entre qué hosts viaja?
OSI 4 / TCP-IP Transporte
TCP / UDP
Puertos, sesiones, flags, control de flujo. Responde: ¿qué proceso se comunica?
OSI 5-7 / TCP-IP Aplicación
DNS / HTTP / TLS
Consultas, respuestas, métodos, nombres, cifrado. Responde: ¿qué servicio se está usando?

06 Cómo leer una captura: del paquete al diagnóstico

Una captura no se analiza línea por línea al azar. Se buscan conversaciones, patrones y cambios de estado. La pregunta central es: ¿qué intentaba hacer el equipo y en qué punto falló?

01

Ubicar a los participantes

Identificar IP origen, IP destino, MACs locales y gateway. En una LAN, ARP suele aparecer antes de una comunicación IP.

02

Separar protocolos

Filtrar por `dns`, `tcp`, `icmp`, `http` o una IP específica. Esto reduce ruido y permite seguir una conversación.

03

Mirar el orden

En TCP debería verse SYN, SYN/ACK, ACK antes de los datos. En DNS debería verse consulta y respuesta.

04

Buscar síntomas

Retransmisiones, resets, destinos inalcanzables, consultas DNS sin respuesta, puertos cerrados o latencia elevada.

05

Relacionar con capas

Si falla ARP, el problema está en capa 2. Si responde DNS pero no TCP, mirar capa 4. Si TCP conecta pero HTTP falla, mirar aplicación.

07 Apéndice: 10 propuestas prácticas de captura

Estas prácticas sirven para generar tráfico real, capturarlo y analizarlo en Wireshark. Realizarlas en una red de laboratorio o con autorización.

01

ARP en red local

Vaciar caché ARP, hacer ping al gateway y capturar `arp`. Analizar quién pregunta y quién responde.

02

DHCP al obtener IP

Capturar el proceso Discover, Offer, Request, ACK al renovar dirección IP.

03

DNS de un sitio web

Abrir un dominio nuevo y filtrar `dns`. Identificar consulta, respuesta, tipo A/AAAA y servidor DNS.

04

Ping e ICMP

Ejecutar `ping` al gateway y a una IP externa. Comparar Echo Request, Echo Reply, TTL y tiempos.

05

Handshake TCP

Conectarse a un servidor web y filtrar `tcp.flags.syn == 1`. Identificar SYN, SYN/ACK y ACK.

06

HTTP sin cifrar

Acceder a un sitio HTTP de prueba y filtrar `http`. Ver método GET, host y código de respuesta.

07

TLS/HTTPS

Abrir un sitio HTTPS y filtrar `tls`. Identificar Client Hello, Server Hello y datos cifrados.

08

Puertos abiertos y cerrados

Probar conexión a un puerto abierto y otro cerrado. Comparar SYN/ACK contra RST.

09

Traceroute por saltos

Ejecutar `traceroute` o `tracepath` y observar ICMP Time Exceeded o UDP/ICMP según la herramienta.

10

Docker y puertos publicados

Levantar un contenedor web, acceder al puerto publicado y analizar la conexión desde cliente a servidor.
