Capa 3 del modelo OSI
Direccionamiento y enrutamiento

Presentación interactiva para comprender cómo la capa de red identifica dispositivos con direcciones IP, agrupa redes con máscaras de subred y encamina paquetes entre routers hasta llegar a destino.

Comenzar explicaciónIr a práctica
01¿Qué hace la capa 3?

La capa de red se encarga de dos tareas centrales: darle una dirección lógica a cada dispositivo (la IP) y decidir por dónde encaminar cada paquete para que llegue de una red a otra. Mientras la capa 2 solo entrega tramas dentro de una misma LAN usando direcciones MAC, la capa 3 permite que los datos crucen múltiples redes distintas hasta llegar a cualquier parte del mundo.

Idea clave
La capa 2 entrega tramas dentro de una LAN usando MAC. La capa 3 entrega paquetes entre redes distintas usando IP, atravesando uno o varios routers en el camino.

06Direcciones privadas y NAT

Existen rangos reservados para redes privadas que no son ruteables en internet. Los routers domésticos y empresariales usan NAT (Network Address Translation) para traducir esas direcciones privadas a una IP pública cuando salen hacia internet.

Siempre apunta al propio equipo. Se usa para pruebas locales.
Cómo funciona NAT
El router recuerda qué equipo interno originó cada conexión y reemplaza la IP privada por su propia IP pública al salir. Cuando llega la respuesta, hace la traducción inversa para entregarla al equipo correcto.
07Enrutamiento: routers y tablas de ruteo

Un router conecta redes distintas y decide, paquete por paquete, hacia qué interfaz o siguiente salto reenviarlo. Esa decisión se toma consultando su tabla de ruteo: si varias rutas coinciden con la IP destino, gana la que tiene el prefijo más específico (longest prefix match).

09ICMP y ARP: los ayudantes de la capa 3

Además de IP, la capa 3 se apoya en dos protocolos clave para diagnosticar y resolver direcciones.

ICMP · protocolo 1
Mensajes de control y error
ping usa ICMP Echo Request/Reply para probar conectividad. traceroute usa mensajes "TTL exceeded" para descubrir cada router del camino. También reporta errores como "Destination unreachable".
ARP · frontera capa 2/3
Resuelve IP a MAC
Antes de entregar un paquete dentro de la LAN, el equipo pregunta por broadcast "¿quién tiene esta IP?" para obtener la dirección MAC correspondiente y armar la trama.
Comandos y filtros
ping 8.8.8.8
traceroute 8.8.8.8      # Linux/Mac
tracert 8.8.8.8         # Windows
arp -a

Filtros Wireshark:
icmp
arp
icmp.type == 11   (TTL exceeded, típico de traceroute)
icmp.type == 8    (Echo Request)
icmp.type == 0    (Echo Reply)
Qué observar
En una traza de traceroute, cada salto responde una vez con TTL agotado; el último salto (el destino) responde con Echo Reply. Un router que no contesta suele mostrarse como * o tiempo agotado.
